# Road3 作动器一阶惯性模型一致性检查

## 问题

论文动力学方程通常把主动悬架作动器建模为一阶惯性环节：

```text
tau * du_a/dt + u_a = u_cmd
```

但 CarSim 外部悬架力 `IMP_FS/FsExt` 更接近直接力输入：Simulink 给多少，CarSim 当前步就按该外部力作用。若预测模型包含一阶惯性，而真实 CarSim 通道没有同样的一阶响应，会造成控制律预测与实际对象不一致。

## 代码检查结论

该问题在当前代码中确实存在。

### 离线预测模型

`src_2020/config_2020.m`：

```matlab
cfg.tau = 0.05;
cfg.n_x = 5 + cfg.n_road;
```

`src_2020/Step1_BuildPredictionModel_2020.m` 和 `src_nonlinear/TrainNonlinearSuspensionOffline_2020.m` 中均把作动力作为第 5 个状态：

```matlab
A_qc(...,5) = -1/tau;
B_qc = [0; 0; 0; 0; 1/tau];
```

并且车身/轮端加速度方程使用 `u_a`：

```matlab
... -1/m1 * u_a
... -(1/m1 + 1/m2) * u_a
```

因此离线 MPC 训练出来的控制律假设：控制量先经过 `tau=0.05 s` 一阶作动器，实际作用力是滞后的 `u_a`。

### 在线状态估计

`src_2020/per_corner_mpc_state_step_2020.m` 中也按同样时间常数估计内部作动力状态：

```matlab
alpha_a = exp(-dt_val / tau_val);
ua = alpha_a * ua + (1 - alpha_a) * up;
x(5) = ua;
```

`src_nonlinear/per_corner_mpc_nonlinear_step_2020.m` 传入：

```matlab
tau_val = 0.05;
```

因此在线显式 MPC 的状态向量也认为当前实际作动力是 `u_prev` 经过 `0.05 s` 一阶滤波后的 `ua`。

### 实际 CarSim 输入

当前 CarSim 外部力通道没有发现等效 `tau=0.05 s` 作动器模型。现有 Simulink/代码层只有：

1. Unit Delay: `0.001 s`
2. `road3_bump_safe_output_2020` 输出层平滑：
   - 前轴 `smooth_tau_s = 0.015 s`
   - 后轴 `smooth_tau_s = 0.020 s`
3. rate limit:
   - 前轴 `15000 N/s`
   - 后轴 `9000 N/s`

这些不等价于离线模型中的 `tau=0.05 s` 一阶作动器。

## 影响判断

这是一个真实风险，尤其会影响 Road-3 凸包这种瞬态激励。

以 `tau=0.05 s` 估算：

- 10 ms 后作动力只达到目标约 `18%`
- 20 ms 后约 `33%`
- 50 ms 后约 `63%`

而 T1 短凸包 `0.4 m / 30 km/h` 持续时间约 `48 ms`，T2 长凸包 `2.5 m / 50 km/h` 持续时间约 `180 ms`。因此作动器时间常数会显著影响相位和峰值预测。

如果 CarSim 实际为直接力输入，而 MPC 认为力会慢慢建立，那么控制器会在预测中低估当前控制力的即时影响，可能导致：

1. 瞬态凸包中过早或过强输出；
2. `u_prev/ua` 状态估计偏离真实 `FsExt`；
3. 与 `Gain` 符号、`UV_POS/UV_NEG` 门控、输出平滑共同产生复杂耦合。

## 是否应该在 Simulink 中加入延迟/惯性

不建议加入“纯延迟”。纯 delay 与一阶惯性不是同一物理模型，会增加额外相位滞后，容易让凸包工况更差。

可选方案有两个：

### 方案 A：模型跟随论文，给 CarSim 输入增加一阶作动器

在每个 `IMP_FS_*` 前加入离散一阶滤波：

```text
u_act[k+1] = alpha * u_act[k] + (1-alpha) * u_cmd[k]
alpha = exp(-dt/tau)
tau = 0.05 s
```

然后把 `u_act` 送入 CarSim，并把 `u_act` 作为 `u_prev` 反馈给 MPC。

优点：

- 与论文和当前离线模型一致。
- 不需要立刻重训离线数据。

缺点：

- 作动器变慢，瞬态凸包控制能力下降。
- 当前已经有输出层 smoothing/rate limit，若再加 `tau=0.05 s` 可能过度滞后。

### 方案 B：模型跟随 CarSim，重训快作动器/直接作动器控制律

保持 CarSim 直接力输入，不额外加入物理一阶作动器；把离线模型中的 `tau` 改小，或重构为直接力输入模型。

建议先做低风险版本：

```text
tau = 0.005 s 或 0.001 s
```

保持 5 状态结构不变，避免立即重写 QP direct feedthrough 逻辑。

优点：

- 更符合 CarSim 当前外部力通道。
- 更适合追求仿真性能。

缺点：

- 与论文的作动器一阶假设不完全一致。
- 需要重新训练 nonlinear profile。

## 当前推荐

当前阶段不建议直接在 Simulink 里加 `tau=0.05 s` 作动器。更推荐先做 **方案 B**：

1. 保持 CarSim 外部力直接输入。
2. 新训练一个 nonlinear 快作动器 profile：
   - `ROAD3_NONLINEAR_QC_LONGTRAVEL_TAU005_V1`
   - `cfg.tau = 0.005`
3. 如仍存在明显相位问题，再训练：
   - `ROAD3_NONLINEAR_QC_LONGTRAVEL_TAU001_V1`
4. 对 T2 50 mm pilot 和正弦波路面同时验证。

只有在目标明确转为“严格复现论文一阶作动器假设”时，才在 Simulink 中加入与模型完全一致的 `tau=0.05 s` 一阶作动器环节。

## 后续验证要求

无论选择哪条路线，都必须导出或记录：

- controller raw command `u_cmd_raw`
- output guard 后的 `u_safe`
- 最终送入 CarSim 的 `FsExt/IMP_FS`
- 内部估计状态 `ua`

否则无法判断是 MPC 预测模型、输出层、Gain 符号、还是 CarSim 实际输入造成差异。
