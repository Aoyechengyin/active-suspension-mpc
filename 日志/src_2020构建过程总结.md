# src_2020 构建过程总结

> 日期：2026-06-03  
> 目标：为 CarSim 2020 + Simulink 联合仿真创建独立的 `src_2020/` 代码与数据，不改动原 `src/`。

## 1. 构建目标与最终产物

本次实现围绕 1 ms 扩展版 Regionless e-MPC，而不是论文原始 10 ms 基线：

- 采样周期：`dt = 0.001 s`
- 预测步长：`p = 80`
- 控制步长：`c = 10`
- 预瞄路面状态：`N = 20`，即 `w0~w20`，总状态维度 `n_x = 26`
- 预瞄输入：CarSim 输出 `W1/W2`，分别对应 10 ms / 20 ms 后路面高程
- 前后轴分开建模：
  - 前轴：`k1f = 146000 N/m`
  - 后轴：`k1r = 46000 N/m`
  - 后悬 Big SUV 阻尼表按 `|v| <= 0.20 m/s` 最小二乘拟合，得到 `c1r ≈ 7949.1 N/(m/s)`
  - 前悬暂用同一等效阻尼 `c1f = c1r`

新增目录与主要文件：

```text
  Step1_BuildPredictionModel_2020.m

  regionless_mpc_data_front.mat / regionless_mpc_data_rear.mat
```

## 2. 实现流程

### 2.1 创建自检入口

先创建 `self_check_2020.m`，作为 `src_2020` 的结构自检入口，检查：

- 必要脚本是否存在
- `config_2020()` 参数是否符合计划
- `dt/p/c/N/n_x` 是否分别为 `0.001/80/10/20/26`
- CarSim Export 顺序是否为当前模型的 W-first 24 路顺序

最初运行自检时，预期失败，因为 `config_2020.m` 等文件尚未创建。这一步用于确认自检确实能捕捉缺失产物。

### 2.2 创建参数配置

创建 `config_2020.m`，集中管理：

- 车辆参数：簧上质量、前后簧下质量、前后悬架刚度、轮胎刚度
- MPC 参数：`dt/p/c/N/u_max/tau/rho`
- 几何参数：`a=1.18 m`，`b=1.77 m`，`L=2.95 m`
- 后悬 Big SUV 阻尼表
- 后悬阻尼等效线性拟合规则
- CarSim Export 24 路顺序

后悬阻尼等效拟合结果：

```text
|v| <= 0.20 m/s: c1r ≈ 7949.1 N/(m/s)
```

### 2.3 构建前后轴预测模型

创建 `Step1_BuildPredictionModel_2020.m`：

- 以前后轴参数分别构建 quarter-car + actuator + road shift-register 模型
- 每套模型为 26 维：
  - 5 个 QC/执行器状态
  - 21 个路面状态 `w0~w20`
- 输出：

```text
prediction_model_front.mat
prediction_model_rear.mat
```

验证输出：

```text
front: n_x=26, dt=0.0010, k1=146000, c1=7949.1
rear : n_x=26, dt=0.0010, k1=46000,  c1=7949.1
```

### 2.4 构建 QP 矩阵

创建 `Step2_BuildMPCmatrices_2020.m`：

- 根据预测模型构建 `Phi/Gamma/Psi/Upsilon`
- 构造标准 QP：

```text
min 0.5 * U' * H * U + x' * F * U
s.t. P * U <= M1 + M2 * x
```

- 输出：

```text
mpc_qp_data_front.mat
mpc_qp_data_rear.mat
```

验证输出：

```text
H = 10 x 10
P = 20 x 10
M2 = 20 x 26
```

### 2.5 构建 Regionless e-MPC 离线数据

创建 `Step3_RegionlessSolver_2020.m`：

- 随机采样状态空间
- 对每个采样点求解 QP
- 识别活跃集
- 预计算 KKT 映射
- 保存 codegen-safe 数据：

```text
regionless_mpc_data_front.mat
regionless_mpc_data_rear.mat
```

最终 8000 点采样结果：

```text
front: n_sets=282, validation_max_error=8.7257e-09, validation_misses=7
rear : n_sets=300, validation_max_error=6.1988e-08, validation_misses=1
solver=gurobi
```

说明：

- `validation_max_error` 只统计 regionless 找到可行活跃集的点，与直接 QP 对比误差小于 `1e-7`
- `validation_misses` 表示采样枚举未覆盖到的随机验证点，在线控制器会退回无约束/限幅解；后续可通过增加采样数或更系统的活跃集枚举减少 miss

### 2.6 创建四角在线控制器

创建公共 step 函数：

```text
per_corner_mpc_state_step_2020.m
```

创建四个 wrapper：

```text
per_corner_mpc_L1_2020.m  -> 加载 front 数据
per_corner_mpc_R1_2020.m  -> 加载 front 数据
per_corner_mpc_L2_2020.m  -> 加载 rear 数据
per_corner_mpc_R2_2020.m  -> 加载 rear 数据
```

关键改动：

- 每个 wrapper 自己持有 persistent 状态，避免四角状态串扰
- 输入增加 `pitch_deg`
- 内部对 `pitch_deg` 低通微分得到 pitch rate
- 前轴速度修正：

```text
Vz_front = Vz_SM + a * pitch_rate
```

- 后轴速度修正：

```text
Vz_rear = Vz_SM - b * pitch_rate
```

- 路面状态不再只填 `w0/w10/w20`，而是用 `road_now/W1/W2` 分段线性填充 `w0~w20`

### 2.8 Simulink 到 CarSim 的 Import 输入

本次 `src_2020` 没有改变 CarSim 主动悬架输入变量，预期仍沿用原来的四轮外部悬架力 Import：

```text
IMP_FS_L1    左前悬架外部附加力 (N)
IMP_FS_R1    右前悬架外部附加力 (N)
IMP_FS_L2    左后悬架外部附加力 (N)
IMP_FS_R2    右后悬架外部附加力 (N)
```

但需要区分两件事：

1. 当前 `untitled_2020.slx` 内部 Mux 顺序。
2. CarSim 2020 数据库/`simfile.sim` 实际生成的 Import 通道顺序。

通过 MATLAB API 检查 `src_2020/untitled_2020.slx`，当前根层 `Mux` 接到 `CarSim S-Function` 的顺序为：

```text
Mux input 1 <- Subsystem2 -> per_corner_mpc_L1_2020
Mux input 2 <- Subsystem1 -> per_corner_mpc_R1_2020
Mux input 3 <- Subsystem  -> per_corner_mpc_L2_2020
Mux input 4 <- Subsystem3 -> per_corner_mpc_R2_2020
```

所以当前 Simulink 模型内部的四路控制力顺序是：

```text
[IMP_FS_L1, IMP_FS_R1, IMP_FS_L2, IMP_FS_R2]
```

即对应四个控制器输出：

```text
per_corner_mpc_L1_2020 -> Saturation(+/-9000) -> Gain(-1) -> IMP_FS_L1
per_corner_mpc_R1_2020 -> Saturation(+/-9000) -> Gain(-1) -> IMP_FS_R1
per_corner_mpc_L2_2020 -> Saturation(+/-9000) -> Gain(-1) -> IMP_FS_L2
per_corner_mpc_R2_2020 -> Saturation(+/-9000) -> Gain(-1) -> IMP_FS_R2
```

注意：当前 `src_2020/simfile.sim` 仍显示：

```text
PORTS_IMP 0
PORTS_EXP 0
```

这说明复制出来的 `untitled_2020.slx` 还没有绑定 CarSim 2020 正式生成的 4 路 Import / 24 路 Export 接口。因此上面的 `[L1, R1, L2, R2]` 只能说明 Simulink 当前 Mux 排列，不能单独证明 CarSim 2020 端的 Import 通道顺序。真正联调前必须在 CarSim 2020 的 Send-to-Simulink 生成结果中确认 Import 顺序；如果 CarSim 端实际顺序是 `[IMP_FS_L1, IMP_FS_L2, IMP_FS_R1, IMP_FS_R2]` 或其他排列，就需要改 Simulink 的 Mux 输入顺序，或者在 CarSim Import 列表中重新排序，使两端完全一致。

这里 `Gain=-1` 仍按之前 Simulink 侧的力方向约定保留：MPC 内部输出为控制器计算的作动力，送入 CarSim 的 `IMP_FS_*` 前反号，以匹配 CarSim External Force 对悬架压缩/伸张的正方向定义。

## 3. 报错原因与解决方法

### 3.1 MATLAB 普通沙箱启动失败

报错：

```text
Fatal Startup Error:
System Error: File system inconsistency
```

原因：

- MATLAB 在当前受限沙箱中启动时访问文件系统失败。

解决：

- 按权限规则使用 `matlab -batch` 提升权限运行。
- 提升后 MATLAB 能正常启动，并加载项目路径和工具箱。

### 3.2 `self_check_2020` 找不到 `.slx`

报错：

```text
Missing required file: ...\src_2020\untitled_2020.slx
```

原因：

- `self_check_2020.m` 使用 `exist(file_path, 'file') == 2` 判断文件存在。
- MATLAB 对 `.slx` 这类 Simulink 模型的 `exist` 返回值可能不是普通 M 文件的 `2`。

解决：

```matlab
assert(exist(file_path, 'file') > 0, ...)
```

同类修复也用于 `Step4_CheckSimulink_2020.m` 中对 `.slx` 的判断。

### 3.3 Gurobi 默认变量下界导致 QP 错误

现象：

- Step3 初次采样时 regionless 与直接 QP 误差达到 `9000 N`。

原因：

- MATLAB Gurobi 模型未设置变量上下界。
- Gurobi 默认变量下界为 0，而控制序列 `U` 必须允许负值。

解决：

```matlab
model.lb = -inf(size(f(:)));
model.ub = inf(size(f(:)));
```

### 3.4 Gurobi 二次项缩放与 quadprog 不一致

现象：

- 设置变量无界后，仍出现大误差。
- 单点对比发现：
  - `quadprog(H, f, ...)` 与 `gurobi(Q=H)` 解不一致
  - `quadprog(H, f, ...)` 与 `gurobi(Q=0.5*H)` 解一致

原因：

- 当前 MATLAB Gurobi 接口下，传入 `Q=H` 会导致二次项相对 `quadprog(H,f,...)` 被放大。

解决：

```matlab
model.Q = sparse(0.5 * H);
```

修复后：

```text
front validation_max_error=8.7257e-09
rear  validation_max_error=6.1988e-08
```

### 3.5 活跃集识别阈值过紧

现象：

- 采样识别到的活跃集可能缺少边界约束。

原因：

- 使用 `abs(residual) < 1e-5` 对 Gurobi/quadprog 求解结果识别活跃约束偏紧。

解决：

- 放宽为 `1e-4`
- 保存活跃集前，用同一采样点重构 `U_check`，若与 QP 解误差超过 `1e-3` 则丢弃该活跃集

### 3.6 `local_objective` 局部函数作用域错误

报错：

```text
函数或变量 'local_objective' 无法识别
```

原因：

- `local_objective` 被错误插入到了 `local_fill_road_states` 函数中间，导致 MATLAB 不能识别为独立局部函数。

解决：

- 重新整理 `per_corner_mpc_state_step_2020.m` 的函数结构：
  - `local_fill_road_states` 完整结束
  - 再定义独立的 `local_objective`

修复后四个控制器零输入直接调用：

```text
[0 0 0 0]
```

### 3.7 Step4 找不到 Stateflow chart

报错：

```text
Stateflow chart not found: per_corner_mpc_L1
```

原因：

- Simulink 中 MATLAB Function 块的 Stateflow chart 名称是 `MATLAB Function1/2/3/4`
- 旧函数名 `per_corner_mpc_L1` 等存在于脚本文本中，不是 chart 名称。

解决：

- Step4 不再按 chart 名称查找。
- 改为遍历 `Stateflow.EMChart`，按脚本文本中的函数签名定位对应 chart。

### 3.8 更新模型时 CarSim S-Function 报 solver DLL path 缺失

报错：

```text
'untitled_2020/CarSim S-Function' 中的 S-Function 'vs_sf' 报告错误:
Error: Unable to find solver DLL path from sim file.
```

原因：

- `set_param(model, 'SimulationCommand', 'Update')` 会触发 CarSim S-Function。
- 当前复制模型未绑定 CarSim 2020 生成的 solver DLL/sim 文件路径。

解决：

- Step4 更新 MATLAB Function 端口时临时注释 CarSim S-Function：

```matlab
old_state = get_param(carsim_block, 'Commented');
set_param(carsim_block, 'Commented', 'on');
set_param(model_name, 'SimulationCommand', 'Update');
set_param(carsim_block, 'Commented', old_state);
```

这样能完成 MATLAB Function 端口推断和模型保存，同时不永久禁用 CarSim 块。

### 3.9 Inport 库路径错误

报错：

```text
没有名为 'simulink/Sources/Inport' 的模块
```

原因：

- Simulink 库里 Inport 块路径应为：

```text
simulink/Sources/In1
```

解决：

```matlab
add_block('simulink/Sources/In1', path, ...)
```

### 3.10 左前嵌套子系统接线顺序错误

报错：

```text
Simulink 对象名称无效: 'Subsystem/8'
```

原因：

- 左前控制链路比其他角多一层嵌套：

```text
untitled_2020/Subsystem2/Subsystem/MATLAB Function1
```

- 外层试图连接 `Subsystem/8` 前，内层子系统还没有暴露第 8 个输入端口。

解决：

- 先在内层子系统新增 `pitch_deg` Inport 并连到 `MATLAB Function1/9`
- 再在外层 `Subsystem2` 新增 `pitch_deg` Inport 并连到 `Subsystem/8`

最终 Step4 成功保存模型。

## 5. 当前注意事项

1. `src_2020/slprj/` 是 Simulink 更新模型时生成的缓存目录，当前保留未删除。
2. `regionless_mpc_data_*` 是 8000 点采样生成，仍存在少量未覆盖验证点：
   - front：7 个 miss
   - rear：1 个 miss
3. 未命中时在线控制器会使用无约束解并限幅；如果联合仿真中出现控制力异常饱和，可继续增加采样点数或改用更系统的活跃集枚举。
4. 当前 `untitled_2020.slx` 的 CarSim S-Function 仍需要由 CarSim 2020 正确 Send-to-Simulink 或绑定 solver DLL/sim 文件后，才能完整联合仿真。
5. CarSim Export 顺序必须与模型 Demux 对齐。当前模型按 W-first 24 路设计：

```text
W1_L1,W1_R1,W1_L2,W1_R2,
W2_L1,W2_R1,W2_L2,W2_R2,
Az_SM,Vz_SM,
Jnc_L1,Jnc_R1,Jnc_L2,Jnc_R2,
JncR_L1,JncR_R1,JncR_L2,JncR_R2,
Zgnd_L1,Zgnd_R1,Zgnd_L2,Zgnd_R2,
Vx,Pitch
```

如果 CarSim 2020 实际生成基础 16 路在前、预瞄 8 路在后，需要重新调整 Demux 映射。
